Parte 1

Planificación del Proyecto

Descripción del proyecto

Miss Whitney es una interfaz web para un restaurante real ubicado en la Avenida Escultora Miss Whitney, Huelva. El proyecto incluye: página de inicio con hero animado, galería de platos con filtros interactivos, sistema de reservas, solicitud de facturas, sección de contacto con mapa y sistema de reseñas de Google.

Desarrollado con Laravel 12 + PHP 8.2 como framework backend, Bootstrap 5.3.3 como framework CSS y JavaScript vanilla para la interactividad.

Diseño Responsive

El diseño es mobile-first con tres breakpoints principales: móvil (<600px), tablet (600–860px) y escritorio (>860px). En móvil el topbar se oculta y aparece el dock inferior con navegación por iconos. En tablet, las columnas en grid pasan de 2 a 1.

Proceso de optimización de imágenes

Las imágenes se optimizan con Squoosh (squoosh.app) antes de subirse al servidor:

  • Redimensionado a la resolución de visualización máxima (no mayor de 1200px de ancho)
  • Conversión a WebP con calidad 80%
  • Fallback JPG para navegadores sin soporte WebP
  • Uso de <picture> con <source type="image/webp">
  • Atributo loading="lazy" en imágenes fuera del viewport inicial

Elementos multimedia implementados

Reproductor de vídeo HTML5

Elemento <video> con atributos controls, muted, loop, playsinline y poster. Incluye texto alternativo para navegadores sin soporte.

Carrusel de platos

Carrusel personalizado con JavaScript puro usando requestAnimationFrame y translate3d. Sin dependencias externas. Velocidad de 0.5px/frame. Se pausa al pasar el ratón.

Canvas API

28 partículas doradas/crema animadas con requestAnimationFrame. Respeta prefers-reduced-motion. Usa ResizeObserver para adaptar el canvas al tamaño del hero.

Carrusel de reseñas

Dos filas animadas en sentidos opuestos con datos reales de la API de Google. Se re-mide cuando cargan las imágenes de avatar.

Memoria

Incidencias y Conclusiones

Incidencias durante el desarrollo

Bootstrap JS — Error de integridad SRI

El hash de integridad (integrity) generado para el script de Bootstrap no coincidía con el servido por jsDelivr, provocando que el navegador bloqueara la carga. Solución: Usar la etiqueta sin el atributo integrity o actualizar el hash correcto desde la documentación oficial.

Canvas — Dimensiones 300×150 (valor por defecto HTML)

El canvas se inicializaba con las dimensiones por defecto (300×150px) porque getBoundingClientRect() devolvía 0 al ejecutarse el script antes de que el layout estuviera calculado. Solución: Usar hero.offsetWidth/offsetHeight (elemento padre) + ResizeObserver para redibujar al cambiar el tamaño.

Canvas — prefers-reduced-motion activado

Las partículas no se mostraban en el ordenador de desarrollo porque la configuración de accesibilidad de Windows tenía activada la opción "Reducir animaciones". El script la detecta correctamente y omite el canvas. Conclusión: Comportamiento correcto — demuestra implementación de accesibilidad.

Caché de vistas Blade en producción

El servidor compilaba las plantillas Blade y las almacenaba en caché. Al subir archivos .blade.php actualizados, el servidor seguía sirviendo la versión antigua. Solución: Script clear-cache.php para eliminar las vistas compiladas de storage/framework/views/ sin acceso SSH.

Función showCat() no definida en carta

Los botones de categoría de la página carta llamaban a showCat() pero la función nunca se había definido en ningún archivo JS, causando un error en consola y pestañas no funcionales. Solución: Añadir la función en un bloque @push('scripts') al final de la vista.

Conclusiones

El proyecto Miss Whitney ha resultado en una interfaz web completa y funcional que combina tecnologías modernas (Laravel, Bootstrap 5, Canvas API, HTML5 Video) con buenas prácticas de accesibilidad y rendimiento. Los principales aprendizajes han sido:

  • La importancia del orden de carga de CSS para que los estilos personalizados sobreescriban correctamente los de Bootstrap
  • El comportamiento del Canvas API respecto al layout del navegador y la necesidad de usar offsetWidth en lugar de getBoundingClientRect() en ciertos contextos
  • La media query prefers-reduced-motion como herramienta fundamental de accesibilidad
  • La gestión de caché en entornos de producción Laravel sin acceso SSH
  • La optimización de imágenes con WebP como mejora significativa de rendimiento (30-50% menos peso)
